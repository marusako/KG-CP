# 第17段階: 派生技（ターゲットコンボを含む）

## 目的

決まった技を出している途中に、決まった入力をすると出る続きの技（派生技）を、キャラの動き（フレームメーター）で実際に出す。コマンド練習の一覧とコンボトライアルの手にも使えるようにする。今後キャラを足すときも、同じ形のデータを書けば派生が使えるようにする。

## 決めたこと（開発者の回答）

- 入れる派生: ブリジットのキックスタート マイ ハートの停止・発射、キャミィの 5HP > HK（スイングコンビネーション）、キャミィのフーリガンコンビネーションの派生（すべて）
- 今後足すキャラにも、同じデータの形で使えるようにする
- キャラの動きで派生が出て、コマンド練習の一覧とコンボトライアルの手にも使える

## データの形（今後のキャラでも同じ）

`src/core/frameData.ts`:

```ts
export interface FollowUp {
  /** 親の技のあとに入れるもの。ボタン（例: 'P'、'HK'、'LPLK' は同時押し）と、要るなら方向（例: '2K'） */
  input: string;
  /**
   * 受付。'frames' は親の技を出したフレームを 1 として [from, to] フレーム目の間。
   * 'contact' は親の技が当たったフレームから frames フレームの間（ヒットストップを含む）。当たらなければ受け付けない
   */
  window: { kind: 'frames'; from: number; to: number } | { kind: 'contact'; frames: number };
  /** 派生の技。input は「親の入力 + 区切り + 派生の入力」（例: '236K~P'、'5HP>HK'、'236LP>K'） */
  move: MoveFrames;
}

export interface MoveFrames {
  // …今までの項目…
  /** 派生。ない技は書かない */
  followUps?: readonly FollowUp[];
  /** 投げ。相手がガードでも当たる（反応はヒットの値を使う） */
  throw?: true;
  /** 攻撃の判定がない（サイレントステップなど）。持続の 1 フレーム目に相手に当たらない */
  noHitbox?: true;
}
```

- 自動で出る派生（フーリガンで何も入れないとレイザーエッジスライサー）は、親の技そのものの数字にする（236LP・236MP・236HP の発生前・持続・硬直・有利を、レイザーエッジスライサーの値にする）。派生を入れると、そこで親の技から派生に切り替わる
- 区切りは、GG の派生は `~`、SF6 のターゲットコンボと派生は `>`（FAT の書き方に合わせる）

## キャラの動き（`src/core/fighter.ts`）

- 技を出している間、派生の入力（`FollowUp.input`）が新しく押され、受付の中なら、そのフレームから派生の技を出す（`startup` の 0 フレーム目。キャンセルと同じく、`contact` などの印は外れる）。`canceled` は付けない。派生で出た印として `FighterState.followUp?: true` を付ける
- 受付 `frames`: 親の技を出したフレームを 1 として数えた、親の技のフレーム番号（ヒットストップで止まっていたフレームは数えない）が [from, to] の中。止まっている間に入れた派生は、そのときの番号が受付の中なら予約し、止まり終わった最初のフレームから出す
- 受付 `contact`: 親の技に `contact` があり、当たったフレームから数えて frames フレーム目まで（当たったフレームを 1）。ヒットストップ中に入れたら、キャンセルの予約と同じく、止まり終わった最初のフレームから出す
  - （レビューの提案 2 で追加）当たったフレームちょうど（1 フレーム目）の押しも受け付ける。そのフレームの `stepFighter` はまだ当たりを知らないので、次のフレーム（`contactAge` 2）で、1 つ前のフレームに派生の入力が新しく押されていたら予約にする。`judgeFollowUp` は、当たったフレーム（after の `contactAge` が 1）で派生の入力が押されていたら ok とする（次のフレームで予約になるため）
- 派生の入力の読み方: `parseStep` で読めるボタン（と方向）。方向がなければ、方向は何でもよい。同時押し（'LPLK'）は、両方が押されていて、どちらかがそのフレームで新しく押された。同じ入力が方向つきと方向なしの両方に合うとき（例: 2 + K は '2K' にも 'K' にも合う）は、方向つきを優先する
- `FighterState` に `contactAge?: number` を足す（親の技が当たったフレームを 1 として、いま何フレーム目か。止まっていたフレームも数える。`contact` が外れると消える）
- 派生は、先行入力より優先する（受付の中で派生の入力をしたら、同じフレームに選ばれた技より先に派生を出す）
- 派生の技は、ふつうの技と同じく、当たればキャンセル（`cancels`）や、さらに派生（`followUps`）ができる
- `throw` の技は、相手が「ガード」でもヒットの反応になる（`contactReaction` で、`throw` ならモードによらずヒット。`Contact.kind` も 'hit'）
- `noHitbox` の技は、持続の 1 フレーム目でも相手に当たらない（`stepDummy`）。コンボトライアルの「つながった」の判定にも使わない（当たらない技として扱う）

## 表記（`src/core/notation.ts`）

- `parseStep` が `親~派生`・`親>派生` を読む。`StepInput` に `{ kind: 'followUp'; parent: StepInput; follow: { dirs: Direction[] | null; buttons: string[] }; text: string }` を足す
- 区切りのどちらでもよい（`236K~P` と `236K>P` は同じ）。読めなければ今までと同じ失敗の文

## コマンド練習（`src/core/characters.ts`・`src/main.ts`・`src/ui/commandPanel.ts`）

- キャラのデータ（`MoveData`）に派生の技を足す（`kind: 'followUp'`）。名前は FAT の英語名で、日本語名は付けない（出典を確かめられないため。日本語でも英語名が出る今の決まり）
  - ブリジット: `bridget-ksmh-brake` Brake `['236K~P']`、`bridget-ksmh-shoot` Shoot `['236K~K']`
  - キャミィ: `cammy-swing-combination` Swing Combination `['5HP>HK']`、`cammy-hooligan-cannon-strike` Cannon Strike (Hooligan) `['236P>K']`、`cammy-hooligan-reverse-edge` Reverse Edge `['236P>2K']`、`cammy-hooligan-fatal-leg-twister` Fatal Leg Twister `['236P>LPLK']`、`cammy-hooligan-silent-step` Silent Step `['236P>P']`（レイザーエッジスライサーは自動で出るので項目にしない）
  - ブリジットの 236K の注記（派生は対象外）を消す
- 判定の関数（新規 `src/core/followUp.ts`）:
  ```ts
  export type FollowUpJudge =
    | { ok: true }
    | { ok: false; reason: 'noParent' | 'noContact' }
    | { ok: false; reason: 'early' | 'late'; frames: number };
  /** 派生のボタンを押したフレームの判定。before・after はそのフレームの前後のキャラ（after は stepDummy のあと） */
  export function judgeFollowUp(before: FighterState, after: FighterState, parent: MoveFrames, followUp: FollowUp): FollowUpJudge;
  ```
  - after でその派生の技が始まった、または予約（`after.cancelTo`）になった → ok
  - （レビューの要修正 1 で追加）受付の中なのに、その派生ではない技が始まった・予約になった（例: 236P>K を選んで 2 + K → 236LP>2K が出る）→ other。画面の文は `followUpOther`: `別の技が出ました` / `A different move came out`（下の「出た技」の行で何が出たか分かる）。戻り値の reason に 'other' を足す
  - before の技が親でない → noParent
  - 受付 `frames`: 親の技のフレーム番号 n（止まっていたフレームは数えない。このフレームの分を含む）が from より前 → early（from − n）、to より後 → late（n − to）
  - 受付 `contact`: before に `contact` がない → noContact。`contactAge` が frames を超えた → late（超えた分）
- 派生の項目の試しは「派生の入力のボタンを押した瞬間」。成否は、キャラの動きで決める（入力の履歴だけでは決まらないため）
  - そのフレームで、その派生の技が出た → 成功
  - 親の技が出ていない → 失敗: `followUpNoParent`
  - 親の技は出ているが、受付の前 → 失敗: `followUpEarly(n)`（あと n フレーム遅く）。受付のあと → 失敗: `followUpLate(n)`（n フレーム遅い）。`contact` の受付で親が当たっていない → `followUpNoContact`
- 第16段階の「出た技」の行も、そのまま出す
- キャラなしでは、派生の項目はない

## コンボトライアル（`src/core/comboSim.ts`・`src/core/combo.ts`）

- 手に `236K~P` などを書ける。新しい判定では、その手の技の一覧は派生の技
- 手 k が派生のとき、その親の技が始まっても「違う技」にしない（親の技は手 k の一部）
- 押したフレームとタイミングの数字は、派生のボタンの押し（予約・先行入力はない）。猶予 W は受付の長さ（`frames` は to − from + 1、`contact` は frames）、最速 +N は受付の始まりから
- 窓の判定（キャラなしなど）では、派生の手は、派生のボタンが押された瞬間に成立とする（親の入力は見ない）
- `resolveRecipe` は、派生の手を派生の技に決める。最後でない手の派生が、ヒット硬直にならない技（ダウン・反応のデータなし・攻撃なし）なら null（今までの決めと同じ）。（レビューの要修正 2 で追加）最後の手でも、攻撃のない技（`noHitbox`）しか当たらない手があれば null（攻撃のない技は「つながった」にならないため。窓の判定になる）

## 文（`src/i18n/messages.ts`、日本語と英語）

- `followUpNoParent`: `親の技が出ていません` / `The base move is not out`
- `followUpEarly: (n) => ...`: `早い（あと {n}F 遅く）` / `Too early ({n}F later)`
- `followUpLate: (n) => ...`: `遅い（{n}F 遅い）` / `Too late ({n}F late)`
- `followUpNoContact`: `親の技が当たっていません（当たったときだけ出せます）` / `The base move did not hit (only usable on contact)`
- 技の名前（`moveDisplayName`）は、派生の技なら、キャラのデータの派生の名前と入力（例: `ストップ（停止） (236K~P)`）

## 受け入れ条件

キャラごとに、1 手目（親の技）のボタンを押したフレームを 0。`inputBuffer` = 4。

1. **データ**: 上の表のとおり。どの派生の `move.input` も「親の入力 + 区切り + `FollowUp.input`」。`throw`・`noHitbox` が表のとおり。推測の値はコメントに推測と書く
2. **ブリジット 236K~P**（下のフレームは、親を押したフレームを 0 とする番号。受付の「N フレーム目」は番号 N − 1）: 236K（発生前 9）のあと、8 で P → 派生は出ない。9〜33 のどこかで P → そのフレームから 236K~P（`startup` の 0 フレーム目、`followUp: true`）。34 以降 → 出ない（236K が当たらない状態で確かめる）。ガードの相手に 236K~P が当たると blockstun（有利 -6）
3. **キャミィ 5HP > HK**: 5HP（ヒット。7 で当たり、8〜20 が止まる）のあと、ヒットストップ中に HK → 止まり終わった 21 から 5HP>HK。当たったフレームを 1 として 19 フレーム目（25）まで受け付け、26 では出ない（5HP の硬直のまま）。空振り（相手がダウン中）では出ない
4. **フーリガン**: 236LP のあと何も入れない → 236LP がそのまま進み、49（50 フレーム目）で当たる（KD 48）。18 で K → 派生は出ない。19〜39（20〜40 フレーム目）で K → そのフレームから 236LP>K。40 以降 → 出ない。受付の中で 2 + K → 236LP>2K（方向つきが優先）
5. **投げ**: 236LP>LPLK は、相手が「ガード」でもヒットの反応（ダウン）
6. **攻撃なし**: 236LP>P は相手に当たらない（`contact` なし）
7. **表記**: `parseStep('236K~P')`・`parseStep('5HP>HK')`・`parseStep('236P>LPLK')` が `followUp` になる。`236K~` のような壊れた表記は失敗
8. **コンボトライアル**: キャミィで `5HP` → `5HP>HK`（ヒットストップ中に HK）が完走し、2 手目の猶予は 19F。ブリジットで `2HS` → `236K~P` と書くと、236K の始まりは「違う技」にならず、236K~P が当たったかで決まる（`2HS` → `236K` → `236K~P` のように親を手として書くこともできる。236K はヒットで硬直になる技）
9. **コマンド練習**: `judgeFollowUp` が、親が出ていない → noParent、受付の前 → early（フレーム数）、受付の中 → ok、受付のあと → late（フレーム数）、5HP > HK で 5HP が当たっていない → noContact。画面の派生の項目（例: Brake (236K~P)）は、この結果を `followUpNoParent` などの文にする
10. 画面: メーターで派生が出る、コマンド練習の一覧に派生、コンボの手に派生を書ける（ヘッドレスの Chrome で確かめる）
11. `npm test`・`npm run typecheck`・`npm run build`・`npx madge --circular --extensions ts src` がすべて終了コード 0

今までのテストのうち、236P（フーリガン）を「入れない技」として確かめているもの、5HP の `tc` を対象外として確かめているものは、新しい決めに合わせて直す。

実機との比べ（推測の値: 236K の受付、キャノンストライクの持続、サイレントステップ）は `docs/manual-checks.md` の「22」に書く。

## 実装中に追記

- テストを書く途中で、受付のフレームの書き方（「N フレーム目」と「押したフレームを 0 とする番号」の混在）、236K に反応のデータがあること、受付 frames でヒットストップを数えないこと、投げの `Contact.kind`、方向つきの優先、236P を必殺技のキャンセル先に足すこと、`judgeFollowUp` と `contactAge` を決めて、プランを直した
- 実装で決めた細部: 派生の項目は `CommandDef` を変えずに別の型 `FollowUpDef`（`PracticeDef = CommandDef | FollowUpDef`）。`StepInput` の followUp に `buttons`、派生の入力に同時押しの印 `chord` を足した。成功の文 `followUpOk`（`成立！ 派生が出ました`）を足した。フーリガンの注記は「派生は別の項目で練習します」に書き換えた
- （レビューの要修正 2 件）別の技が出たときの `other`、攻撃のない技だけの手は窓の判定
- （レビューの提案 1・2・4）`followTiming` のコメントを実態に合わせた。当たったフレームちょうどの派生の押しも受け付ける（`followFromPrev`。ヒットストップのない親に contact の受付の派生を付けると、押したフレームが 1 遅れて数えられる。今のデータでは起きない）。2 + LP+LK の確認項目を「22」に足した
- 選ばなかった提案: 派生の優先度を受付より先に決めている（受付が違う派生を同じ親に付けると、低い優先度の派生が出ないことがある。キャラを足すときに直す）、反応のデータがない派生も最後の手なら「完走」になる（第15段階からの最後の手の決めのまま）
