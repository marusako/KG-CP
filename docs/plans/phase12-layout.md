# 第12段階: 練習画面の配置

## 目的

練習画面を、開発者の配置案（画面操作・入力履歴・状態表示・コマンド、コンボ選択・フレームメーター）の形に組み直す。スクロールせずに、入力・結果・メーターが一度に見えるようにする。

## 決めたこと（開発者の回答）

- 状態表示: 今「練習するコマンド」「コンボトライアル」の枠の下にある判定の結果を、真ん中の枠に移す
- キーコンフィグ: 画面操作のバーのボタンで開く（ふだんは隠す）
- 高さ: 1 画面に収める。長い一覧は枠の中だけスクロールする。横幅が狭い画面では縦に並べる
- タブ（コマンド練習／コンボトライアル）: 画面操作のバーに置く

## 画面の形

```
┌───────────────────────── 画面操作 ─────────────────────────┐
│ SF6 / キャミィ  注記  [コマンド練習][コンボトライアル]   [キーコンフィグ][キャラ選択へ][タイトルへ] │
├──────────┬──────────────┬──────────────┤
│ 入力履歴     │ 状態表示          │ コマンド、コンボ選択 │
│              │                  │                  │
├──────────┴──────────────┴──────────────┤
│ フレームメーター                                        │
└────────────────────────────────────────┘
```

- 幅の比は 入力履歴 : 状態表示 : 選択 = 1 : 1.3 : 1.2 くらい（案の見た目に合わせる）
- 横幅が 900px 未満なら、バー・入力履歴・状態表示・選択・フレームメーターの順に縦に並べ、ページ全体をスクロールする

## 各枠の中身

### 画面操作（`createGameBar`）

左から: ゲーム名（とキャラ名）、注記、タブ 2 つ、（右寄せで）「キーコンフィグ」「キャラ選択へ」「タイトルへ」。幅が足りなければ折り返す。

### 入力履歴

今と同じ。枠の高さに入りきらない古い行は見せない（新しい行が上なので、下が切れる）。

### 状態表示（新しい枠）

- コマンド練習: 見出しに選んでいる技の名前（例: 「スパイラルアロー (236K)」）、技の注記、判定の文（大きめの字）、直近の成功率
- コンボトライアル: 見出しに選んでいるレシピの名前、手順の箱、結果の文（大きめの字）、回数と完走率

見出しに選んでいる物の名前を出すのは、一覧をスクロールしても何を練習中か分かるようにするため。

### コマンド、コンボ選択

- コマンド練習: 見出し・検索欄・一覧。一覧だけが枠の中でスクロールする
- コンボトライアル: 見出し・検索欄・一覧・キャラのコンボの注記・JSON の読み込み／書き出し。JSON の部分は折りたたみ（`<details>`、見出し「JSON で読み込む・書き出す」）にして、ふだんは閉じておく。読み込みの結果や「読めない保存データ」の知らせは、折りたたみの外に出す（閉じていても見えるように）

### フレームメーター

今と同じ中身を一番下に置く。右下に固定の「計測」の小窓が重ならないようにする。

### キーコンフィグ

- バーの「キーコンフィグ」を押すと、画面の上に重ねて開く（後ろは暗くする）。もう一度バーのボタンを押すか、中の「閉じる」を押すと閉じる
- 中身と動きは今と同じ。開いている間も、後ろの練習の処理は今までどおり進む
- 閉じるとき、入力待ち・一括設定の途中なら取り消す（`keyConfig.cancel()`）
- 練習画面を出るとき（キャラ選択・タイトルへ）は閉じる
- Esc では閉じない（Esc はすでに「入力待ちの取り消し」に使っているため、1 回の Esc で両方起きるのを避ける）

## 外から見える形（API）

- `createCommandPanel(roots: PanelRoots, commands, notes)` と `createComboPanel(roots: PanelRoots, profile, character)`
  - `interface PanelRoots { select: HTMLElement; status: HTMLElement }`（`src/ui/panelRoots.ts`）。選択の枠を `select` に、状態表示の枠を `status` に足す
  - 返す型（`CommandPanel`・`ComboPanel`）は変えない
- `createGameBar(root, handlers: { onCharSelect; onBack; onKeyConfig })`。返す `GameBar` に `tabs: HTMLElement`（タブのボタンを入れる場所）を足す
- キーコンフィグを包む重ねる層は `main.ts` で作る（`createKeyConfig` は変えない）
- 文（`src/i18n/messages.ts`、日本語と英語）: `barKeyConfig`（キーコンフィグ / Key config）、`kcClose`（閉じる / Close）、`comboJsonSummary`（JSON で読み込む・書き出す / Load / export JSON）

## テストと確かめ方

- 画面（DOM）を確かめるテストはこのリポジトリにない。今回は配置の変更だけで、新しい判定の処理はないので、テストは足さない。足す文は、今の i18n のテスト（日英でキーがそろうか、ハードコードの日本語がないか）が見る
- ヘッドレスの Chrome で、幅 1400×900・1280×720・800×900 の写真を撮り、次を見る
  - 1400×900 と 1280×720: ページにスクロールが出ない。5 つの枠が案の位置にある
  - 800×900: 縦に並ぶ
  - タブを切り替えると、状態表示と選択の両方が入れ替わる
  - キーコンフィグを開く・閉じる
  - 例外が出ない
- レビューの役を 1 回呼ぶ

## 受け入れ条件

1. 上の「画面の形」と「各枠の中身」のとおりに並ぶ
2. 1400×900 と 1280×720 で、ページ全体にスクロールが出ない（一覧が長いときは、その枠の中だけスクロールする）
3. 幅 900px 未満では縦に並ぶ
4. タブの切り替え・判定の結果・コンボの手順の箱・成功率が、今までどおり動く
5. キーコンフィグを開く・閉じる・閉じたときの取り消しが、上のとおりに動く
6. `npm test`・`npm run typecheck`・`npm run build`・`npx madge --circular --extensions ts src` がすべて終了コード 0

画面での見え方・使い心地は `docs/manual-checks.md` の「17」に書く。

## 実装中に追記

- 開いているかは `main.ts` の変数 `keyConfigOpen` で持つ（`HTMLElement.hidden` の型が `boolean | 'until-found'` で、そのまま反転に使えないため）
- キーコンフィグの層は、練習画面の grid の 2〜3 行目に重ねて置く（`grid-row: 2 / 4`）。画面全体を覆わないので、バーのボタンは押せるまま。重ねるため、バー・3 つの枠・メーターも行と列をはっきり決めている（決めないと、grid の自動の配置が重なりを避けて下にずらす）
- 「計測」の小窓（右下に固定）は、フレームメーターの枠の右下の空いた所に乗る。凡例と注記の右に余白を取り、文には重ならないようにした
- 背の低いウィンドウ向けに、3 つの枠の行は最低 240px にする（それより低いとページ全体のスクロールが出る）
- （レビュー後）JSON の折りたたみの見出し（`<summary>`）は、押したらフォーカスを外す（Space・Enter を練習のボタンに割り当てたとき、押すたびに開閉しないように）
- （レビュー後）バーの右のボタンも折り返す。狭い画面では、凡例の右の余白（計測の小窓のため）を外す
- （レビュー後）今回の配置で上書きされて効かなくなった CSS（一覧の下の余白・結果の最低の高さ・キーコンフィグの幅）を消した
- （レビューの提案 A）JSON の「読み込む」「書き出す」ボタンも、押したらフォーカスを外す。キーコンフィグを開いている間は、層の後ろ（3 つの枠とメーター）を `inert` にして、Tab で後ろの検索欄に入れないようにする
- 選ばなかった提案: 開いている間のキーコンフィグのボタンの色、暗いスクロールバー（`color-scheme: dark`）、`100dvh` の代わりの `100vh`、縦並びの境目を `width < 900px` にそろえる
