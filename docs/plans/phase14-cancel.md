# 第14段階: キャンセルとヒットストップ

## 目的

技を当てたとき、決まった技に**キャンセル**（技の途中を打ち切って、次の技を出すこと）できるようにする。実機と同じ猶予でキャンセルを練習できるよう、**ヒットストップ**（当たった瞬間に、キャラも相手も数フレーム止まる時間）も入れ、フレームメーターに出す。

## 決めたこと（開発者の回答）

- ヒットストップを入れ、メーターにも専用の色（白）のマスで出す
- キャンセルは 4 種類すべて: チェーン（SF6。弱攻撃を弱攻撃でキャンセル）・ガトリング（GG。通常技を決まった通常技でキャンセル）・必殺技キャンセル・SA キャンセル（超必殺技でキャンセル）
- GG（ブリジット）も入れる。ヒットストップの一部とキャンセルの猶予は推測を含む
- コンボトライアルの判定（入力のタイミングの窓）は今回は変えない。ダミーに実際に当たったかで判定する形は次の段階

## 前提（このアプリの決め）

- キャンセルできるのは、技が相手に当たったとき（ヒット・ガード）だけ。空振りキャンセルは扱わない
- 相手がダウン中は今までどおり当たらない。なので、623 → SA3 のような「浮いた相手への追撃」は当たらない（空中のコンボは対象外）
- 多段の技も 1 回だけ当たる扱い（第13段階と同じ）。ヒットストップは 1 段目の値
- 対象外: ジャンプキャンセル・ダッシュキャンセル（GG の `j`・`d`）、ターゲットコンボ（SF6 の `tc`）、ドライブラッシュ、ロマンキャンセル
- ヒットストップの長さは、ヒットでもガードでも同じ（FAT の値は 1 つ）。キャラと相手は同じだけ止まるので、有利フレームの数は今と変わらない

## 調べたこと（確認日 2026-11-06）

### スト6（FAT）

出典は前と同じ FAT（https://github.com/D4RKONION/FAT の `src/js/constants/framedata/`）。数字だけを手で写す。

- `hitstop`: ヒットストップのフレーム数（FAT の項目説明 `SF6GameDetails.json` では "Hitstop"）
- `xx`: キャンセルできる先（項目説明では "Cancels To"）。`ch` = チェーン、`sp` = 必殺技、`su` = SA、`su2`・`su3` = SA2・SA3 だけ、`tc` = ターゲットコンボ
- チェーンの先は `extraInfo` の「Chains into stand LP / crouch LP / crouch LK」（5LP・2LP・2LK が持つ）
- `hcWinSpCa`: 必殺技・CA へのキャンセルの「確認の猶予（hit confirm window）」（項目説明では "Specials & CAs"）

### キャンセルの猶予の数え方（推測）

「当たったフレーム（1）＋ ヒットストップ ＋ 残りの持続（持続 − 1）＋ 硬直の最初の 1F」、つまり **1 + ヒットストップ + 持続** が、FAT の `hcWinSpCa` と次のすべてで一致する。

| 技 | ヒットストップ | 持続 | 1 + ヒットストップ + 持続 | FAT の hcWinSpCa |
|---|---|---|---|---|
| 5LP | 9 | 3 | 13 | 13 |
| 5HP | 13 | 3 | 17 | 17 |
| 5LK | 9 | 3 | 13 | 13 |
| 2LP | 9 | 2 | 12 | 12 |
| 2MP | 11 | 3 | 15 | 15 |
| 2MK | 9 | 3 | 13 | 13 |
| 214LP・214MP・214HP | 13 | 4 | 18 | 18 |

FAT にこの数え方の説明はない。数が合うことからの推測。チェーン・ガトリング・SA キャンセルも同じ窓にする（推測）。

キャンセルの技が出るのは、ヒットストップ中に入れたなら、止まり終わったあと（SuperCombo Wiki の解説の抜粋「キャンセルはヒットストップの終わりに出る」。ページは読み込みを断られ、検索結果の抜粋で確認）。

### GG（FAT と Dustloop）

- FAT にヒットストップの数はない。`atkLvl`（攻撃レベル）はある
- ヒットストップは攻撃レベルで決まる。Dustloop の表は、Lv0 = 11、Lv4 = 15 を検索結果の抜粋で確認（ページは読み込みを断られた）。**Lv1 = 12・Lv2 = 13・Lv3 = 14 は推測**（1 段ごとに 1 増えると見た）
- ガトリングの先は FAT の `gatling`、必殺技・SA は `xx` の `sp`・`su`
- ブリジットの 5D の攻撃レベルは `2[4]`。溜めない場合の 2 を使う

## 時間の流れ（例: キャミィの 5LP がヒット、そのあと何も押さない）

フレーム 0 で 5LP を押す。

| フレーム | キャラ | 相手 | 相手の残り |
|---|---|---|---|
| 0〜2 | 発生前 | free | |
| 3 | 持続（1 フレーム目）・**当たる** | ヒット硬直 | 15 |
| 4〜12（9 フレーム） | **ヒットストップ**（持続の 1 フレーム目のまま） | **ヒットストップ** | 15 のまま |
| 13・14 | 持続（2・3 フレーム目） | ヒット硬直 | 14・13 |
| 15〜21 | 硬直 | ヒット硬直 | 12〜6 |
| 22〜26 | 動ける | ヒット硬直 | 5〜1 |
| 27 | 動ける | free | |

- 有利 = 27 − 22 = **+5**（FAT と同じ）
- メーターの色の数: キャラは 緑 3・赤 1・白 9・赤 2・青 7、相手は 黄 1・白 9・黄 14。赤の合計 3・黄の合計 15 は FAT の数と同じ
- キャンセルできるのは、フレーム 3〜15（13 フレーム ＝ `hcWinSpCa`）

## キャンセルの決め

1. キャンセル先は、技ごとの `cancels`（技の入力の並び）にある技だけ
2. キャンセルの窓は「当たったフレーム、ヒットストップ、残りの持続、硬直の最初の 1F」
3. 当たったフレームとそれより前に押した技は、今までどおり先行入力（`buffered`）に入る。ヒットストップの各フレームで、先行入力を 1 古くし（`inputBuffer` を超えたら捨てる）、残っていてキャンセル先なら**予約**（`cancelTo`）にする
4. ヒットストップ中に押したキャンセル先も予約にする（あとから押したもので置き換える）
5. 予約があれば、止まり終わった最初のフレームから、その技を出す（そのフレームが発生前の 0 フレーム目）
6. 止まり終わったあとの窓（残りの持続と硬直の最初の 1F）では、そのフレームで選ばれた技か、先行入力に残っている技がキャンセル先なら、そのフレームから出す
7. キャンセル先でない技は、今までどおり先行入力（硬直が終わってから出る。古くなれば捨てる）
8. キャンセルで出した技も、当たればさらにキャンセルできる（例: 2LK → 2LP → 623HK、214LP → 236236P）

## 外から見える形（API）

### 技のデータ（`src/core/frameData.ts`）

```ts
export interface MoveFrames {
  // …今までの項目…
  /** ヒットストップ（当たったときに、キャラと相手が止まるフレーム数）。反応のデータがある技だけ */
  hitstop?: number;
  /** キャンセルできる先の技の入力（例: ['5LP', '2LP', '2LK', '236LK', …]）。キャンセルできない技は書かない */
  cancels?: readonly string[];
}
```

### キャラ（`src/core/fighter.ts`）

```ts
export interface FighterState {
  // …今までの項目（phase・frame・move・buffered・contact）…
  /** 当たったあと、このあと止まるフレーム数。stepDummy が当たったフレームに技の hitstop を入れる */
  hitstop?: number;
  /** このフレームはヒットストップで止まっていた（stepFighter が付ける。止まっていないフレームでは付けない） */
  frozen?: true;
  /** ヒットストップ中に予約したキャンセル先の技。止まり終わった最初のフレームで出す */
  cancelTo?: MoveFrames;
  /** いまの技はキャンセルで出した（新しい技を出す・動けるようになると消える） */
  canceled?: true;
}
```

`stepFighter(state, history, fighter, rules, inputBuffer)` の引数は変えない。動きは次のとおり。

- `state.hitstop` が 1 以上: このフレームは止まる。`phase`・`frame`・`move` は変えず、`frozen: true` を付け、`hitstop` を 1 減らす（0 になったら消す）。先行入力は上の「キャンセルの決め」の 3・4 のとおり（新しく選ばれた技は先行入力に入れ、キャンセル先なら予約にする）
- 止まっていないフレームでは `frozen` を付けない
- 予約（`cancelTo`）があれば、そのフレームから予約の技を出す（`phase: 'startup'`・`frame: 0`・`canceled: true`。`contact`・`cancelTo` は消える）
- `contact` があり、進めた結果が「持続」か「硬直の 0 フレーム目」になるフレームで、選ばれた技か先行入力に残っている技が `move.cancels` にあれば、そのフレームからその技を出す（`canceled: true`）
- それ以外は今までどおり

### 相手（`src/core/dummy.ts`）

`stepDummy(dummy, fighter, mode)` の引数と返す形は変えない。

- `fighter.frozen` なら、相手は止まる: 同じ `dummy`・同じ `fighter`・`contact: null` を返す
- 当たったら、今までの `contact: true` に加えて、技に `hitstop`（1 以上）があれば `fighter.hitstop` にその値を入れる
- 当たる条件は今までどおり（持続の 1 フレーム目。止まっているフレームでは当たらない）

### フレームメーター（`src/core/frameMeter.ts`）

- `StateKind` に `'hitstop'` を足す。`meterKindOf(state)` は `state.frozen` なら `'hitstop'`
- `FrameMeterCell.opponent` に `'hitstop'` を足す。キャラが止まっているフレームの相手は `'hitstop'`
- `FrameMeterCell` に `cancel?: true`（このフレームで、キャンセルで技が始まった）、`MoveStart` に `cancel?: true` を足す
- `advantage` の「キャラが動けるようになった最初のマス」を、当たったマスより後で「キャラの段が 発生前・持続・硬直・ヒットストップ のどれでもないマス、または `cancel` のない技の始まりのマス」にする（キャンセルした所では有利を決めず、キャンセルで出した技の終わりまで待つ。先行入力で硬直のすぐあとに出た技は、今までどおり動けるようになったマスとして数える）。相手の側は今までどおり「相手が free の最初のマス」（止まっているマスは free ではない）
- `FRAME_METER_MAX` を 120 → **240**（ヒットストップの分だけ帯が長くなるため。ブリジットの 5S → 2S → 2HS → 236K は約 140 マス）

### 文（`src/i18n/messages.ts`、日本語と英語）

- `cancelPrefix`: `キャンセル: ` / `Cancel: `（キャンセルで出した技の文の頭に付ける）
- `frameMeterLegend` に「白: ヒットストップ（両者が止まる）」/ `White: hitstop (both freeze)` を足す

### 画面

- キャラの段・相手の段とも、ヒットストップのマスは白（`.fm-top.hitstop`・`.fm-opp.hitstop`）。キャラの段の長さの数字は、ヒットストップの区間にも付く（例: 9）
- ヒットストップ中に押したボタンのマスは、今までどおり先行入力の橙の枠になる
- 技の文: キャンセルで出した技は頭に `キャンセル: ` を付ける。例: `しゃがみ中K (2MK) — … / ヒット +1F → キャンセル: キャノンスパイク (623HK) — … / ダウン（つながった） +22F`
- 凡例に白のヒットストップを足す

## 受け入れ条件

フレームは、最初の技のボタンを押したフレームを 0 として数える。先行入力は 4 フレーム（`inputBuffer = 4`）。

1. **データ**: キャミィ・ブリジットの `hitstop`・`cancels` が上の表のとおり。反応のデータ（`onHit` か `onBlock`）がある技は、すべて `hitstop` が 1 以上。`cancels` の入力は、すべて同じキャラの技にある。上の猶予の表の技は「1 + hitstop + active」が FAT の `hcWinSpCa` と同じ（テストに FAT の値を書く）
2. **ヒットストップ**: キャミィの 5LP（ヒット）で何も押さないと、上の「時間の流れ」の表のとおり。止まっている 4〜12 は `frozen: true` で、キャラは持続の 1 フレーム目のまま、相手の残りは 15 のまま。メーターの帯は、キャラの段が 緑 3・赤 1・白 9・赤 2・青 7、相手の段が 黄 1・白 9・黄 14、`advantage` が +5。ガードなら止まるのは同じ 9 フレームで、`advantage` は -2
3. **チェーン**: 5LP（ヒット）のあと、4〜12 のどこかで 2LP を押すと、2LP は 13 から出る（`canceled: true`）。13・14・15 で押すと、そのフレームから出る。16 で押すとキャンセルにならない（16 のキャラは硬直のまま）。チェーンの 2LP は `combo: true`
4. **キャンセル先でない技**: 5LP（ヒット）のヒットストップ中に 5MP を押しても、キャンセルにならない（13 は 5LP の持続の 2 フレーム目）
5. **当たる前の先行入力**: 2MK（発生前 7。7 で当たり、8〜16 が止まる）の発生前に 236HK を入れ終えたとき、入れ終えたのが 4 以降なら 17 から 236HK が出る（`canceled: true`）。3 以前なら、8 の時点で古くなりすぎているのでキャンセルにならない
6. **必殺技キャンセルのコンボ**: 2MK（ヒット）→ 623HK を止まっている間に入れると、623HK は 17 から出て、23 で当たり、`combo: true` のダウン。2MP（ヒット）→ 214LP も `combo: true`
7. **SA キャンセル**: 214LP（ヒット。20 で当たり、21〜33 が止まる）→ 止まっている間に 236236P を入れると、34 から出て 42 で当たり、`combo: true` のダウン。5HK（キャンセル先なし）のヒットストップ中に 236236P を入れてもキャンセルにならない
8. **ガトリング**: ブリジットで 5S → 2S → 2HS → 236K を、それぞれ前の技のヒットストップ中に入れると、どれも `canceled: true` で、当たるフレームは 6・31・55・79。2S・2HS・236K は `combo: true`。5K のヒットストップ中に 2S を入れてもキャンセルにならない（5K の先にない）
9. **キャンセルのあとの有利**: 2MK（ヒット）→ 236HK（反応のデータなし）とキャンセルすると、帯の `advantage` は -30（相手が動けるのは 38、キャラが動けるのは 236HK の終わりの 68）。キャンセルした所（17）では決めない
10. **メーターの印**: キャンセルで技が始まったマスと、その `MoveStart` に `cancel: true`。止まっているマスは、キャラの段が `'hitstop'`、相手の段が `'hitstop'`。`FRAME_METER_MAX` は 240
11. **画面**: 白のマス・凡例・技の文の `キャンセル: ` が上のとおり（ヘッドレスの Chrome で確かめる）
12. `npm test`・`npm run typecheck`・`npm run build`・`npx madge --circular --extensions ts src` がすべて終了コード 0

今までのテストのうち、キャミィ・ブリジットの実データで `stepFighter` と `stepDummy` を一緒に進めるものは、ヒットストップの分だけフレームがずれる。test-writer は、その期待値をヒットストップを入れた値に直す（`FRAME_METER_MAX` の 120 も同じ）。直した所はテストのコメントか報告に書く。

## 実装中に追記

- テストの直し（実装の前）: 214LP → 236236P のテストが SF6 にないボタン `'P'` を送っていたので `'HP'` にした。空振りの 5LP のテストの「5 に押した 2LP が 13 に出る」は、先行入力（4 フレーム）の決まりと合わないので、「5 に押したものは捨てられる」「9 に押したものは 13 に先行入力として出る」に分けた
- 実装で決めた細部: 止まり終わったフレームで、予約と新しく選ばれた技がどちらもキャンセル先なら、新しいほうを出す。止まっているフレームの相手の段は、相手の状態によらず `'hitstop'`
- （レビューの提案）コメントの事実と推測を分けた（ヒットでもガードでも同じヒットストップを使うのは、このアプリの決め）。先行入力の説明にキャンセルでの使い方を足した。技の hitstop が 1 以上のときだけ `fighter.hitstop` を入れる。型ガードの重ねた `as` を外した。確認項目の 19 に、ダウンさせた技からの SA キャンセルは当たらないこと（有利は SA の終わりで決まる。2MK → 623HK → 236236P で +16）を足した

  - 暗いスクロールバー（`color-scheme: dark`）。帯が長くなり、明るいスクロールバーが出やすくなった
