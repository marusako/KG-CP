# 手で確かめること（チェックリスト）

自動テスト（`npm test`）では確かめられない、ブラウザや実機での確認をまとめる。
確認したら `[ ]` を `[x]` にする。気になったことは各節の「メモ」に書く。
新しい段階を作ったら、その確認をここに足す。

## 準備

- 公開版: https://marusako.github.io/KG-CP/
- ローカル版: `npm run dev` を実行し、表示された URL を開く（止めるときは `Ctrl + C`）
- 使うデバイス: キーボード、パッド（あれば Xbox 系と PlayStation 系の両方）
- 初期のキー: 方向 WASD、パンチ U I O（LP MP HP）、キック J K L（LK MK HK）

### 5. キーコンフィグ（第4段階・変更 1）

操作中のデバイスと図:
- [ ] 「操作中: キーボード」と出る。パッドに触ると「操作中: （パッドの名前）（PlayStation 式 / Xbox 式）」に変わり、図もパッドに切り替わる
- [ ] パッドをつないで最初に押したボタンで、もう切り替わる
- [ ] 「キーボード」「パッド」のタブで手動で切り替えると、自動では切り替わらなくなる。「自動」で元に戻る
- [ ] パッドのボタン名が、パッドに合った表記（A/B/X/Y か ×/○/□/△）になる。分からないパッドは番号になり、文字が重ならない
- [ ] 図の各ボタン・キーに、割り当てた操作（LP など）が書かれている
- [ ] 押したボタン・キーが図で光る。左スティックを倒すと点が動く
- [ ] 「いまの入力（キーボード / パッド）: ↘ + LP」のように、図のデバイスの入力が出る
- [ ] キーボードとパッドで図を切り替えても、画面の配置が崩れない
- [ ] キーボードの図の文字が読める大きさ

まとめて設定:
- [ ] 「まとめて設定（キーボード）」で、上 → 下 → 左 → 右 → LP …の順に聞かれ、押したキーが割り当たる
- [ ] 「まとめて設定（パッド）」で、LP〜HK の 6 つが順に聞かれる
- [ ] 同じキー・ボタンを 2 回使うと「すでに ◯◯ に使っています」が出て、先に進まない
- [ ] パッドで十字キーを押すと、受け付けずに理由が出る
- [ ] Esc か「取り消し」で、何も変わらずに終わる
- [ ] キーを長押ししても、すぐにエラーが出ない
- [ ] 設定中に押した入力で、コマンド練習やトライアルが進まない
- [ ] 設定し終わった直後に押したキーが、ちゃんと効く（1 回目が捨てられない）
- [ ] 最後のボタンを押したまま設定を終えても、そのボタンが「押した」扱いでゲームに入らない（離して押し直すと入る）

個別に直す:
- [ ] 一覧の操作（例: 「LP: U」）をクリックしてキーかボタンを押すと、その操作だけ変わる
- [ ] ほかの操作が使っているキーを選ぶと、入れ替わって「◯◯と入れ替えました」と出る
- [ ] 入力待ちで Esc を押すと、何も変わらずに終わる

そのほか:
- [ ] ページを再読み込みしても、割り当てが残っている
- [ ] Space や Enter を割り当てても、プレイ中にボタンが勝手に押されたり、チェックボックスが切り替わったりしない
- [ ] パッドを抜くと「操作中」がキーボードに戻る

### 14. 入力のフレームメーター（第9段階）

計画は `docs/plans/phase9-input-meter.md`。技のフレームデータは使わない（自分の入力だけを見る）。

- [ ] 練習画面（コマンド練習・コンボトライアルの両方）の入力履歴の上に「フレームメーター」の帯がある。最初は何も出ていない
- [ ] 帯は 1 フレーム 1 マスで、方向の矢印が入力履歴と同じ記号で出る。ボタンを新しく押したマスは色が変わり、下にボタン名が小さく出る。ボタンを押しているあいだのマスは薄く色が付く。色は 3 つ程度で、線が細く見やすい
- [ ] 初めは「ボタンで止める」が選ばれている。方向を入れても帯は動かず、ボタンを押した瞬間に、そこまでの 60 フレームの帯に入れ替わって止まる。押しっぱなしでは入れ替わらない。離して押し直すと入れ替わる
- [ ] 「流す」にすると、いまの入力が流れ続ける。「ボタンで止める」に戻すと、そのときの帯のまま止まり、次にボタンを押すまで変わらない
- [ ] 帯の下に、同じ方向が続いた区間のまとめが出る。例: 2 を 3F、3 を 1F、6 を 2F 押して 6 の 2F 目でボタンを押すと `2 (3F) → 3 (1F) → 6 (2F) + P`。複数のボタンは `+ P + K`
- [ ] 選んだモードは保存されない（再読み込みや練習画面に入り直すと「ボタンで止める」）。練習画面に入り直すと帯は空に戻る
- [ ] English で、見出しが「Frame meter」、切り替えが「Stop at button / Live」になる。まとめの文は日本語と同じ形
- [ ] スマホ幅（ブラウザを狭くする）で、帯だけが横にスクロールし、マスは小さくならない。ページ全体は横にはみ出さない

### 15. 棒人間と技のフレームメーター（第10段階）

計画は `docs/plans/phase10-fighter.md`。技のフレームデータの出典は FAT（クレジット画面にも書いた）。相手・当たり判定・有利不利・空中技は 2 段目。

- [ ] 練習画面（コマンド練習・コンボトライアルの両方）のタブの上、入力のフレームメーターより上に、横長のステージと「技のフレームメーター」がある。ステージには床の線と、右向きの棒人間が 1 人いる（線だけ、色は 2 色まで）
- [ ] 棒人間の動き: 何も押さないと立つ。2（下）でしゃがむ。6 で前へ、4 で後ろへ歩く（脚が交互に動く）。歩くと画面の端で止まる。8・7・9 で、一度しゃがんでから跳び、着地でまたしゃがむ。前ジャンプは前へ、後ろジャンプは後ろへ進み、垂直は動かない。空中でボタンを押しても何も出ない
- [ ] 技（キャミィを選ぶ）: 5LP・2MK などの通常技で、構え → 手か足を伸ばす（伸ばしている間は伸ばした手足が赤）→ 戻す、の順に動く。P 系は腕、K 系は脚を伸ばす。2 系はしゃがんだまま出る
- [ ] 技ごとのメーター: 技を出すと、下の帯が空になって 1 フレーム 1 マスで積まれる。発生前は緑、持続は赤、硬直は青。技が終わると帯が止まって残り、次の技を出すと入れ替わる。ジャンプや歩きでは帯は動かない
- [ ] 帯の下の文が `立ち弱P (5LP) — 発生 4F / 持続 3F / 硬直 7F / 全体 13F` の形で出る（技名は選んだ言語。必殺技は `スパイラルアロー (236LK)` のようにキャラの技名）。5LP は緑 3 マス・赤 3 マス・青 7 マス（全体 13）。236LK は全体 42、236236K は 62。5HK と 2MP は空振りの硬直（全体 34・26）。ブリジットも同じ形（5P は全体 23、632146S は 102）で、必殺技は日本語名（スターシップ (623P) など）
- [ ] 数字の食い違い（GGST のトレーニングモードで確かめる）: スターシップの発生は FAT と wikiwiki のフレーム表では 9F だが、wikiwiki のコマンド技のページには「Ver2.03 で 10F→7F」とある。ロック ザ ベイビーの発生は FAT が 27F、wikiwiki のフレーム表が 26F。アプリは FAT の値
- [ ] 必殺技: キャミィで 236 + LK を出すと 5LK ではなく 236LK の帯（全体 42）になる。236236 + K は 236K ではなく 236236K（全体 62）。キャミィの 236 + LP（フーリガン）や 214 + K（データなし）は、棒人間も帯も何も出ない。ブリジットの 63214 + P が Rock the Baby（全体 56）、214 + S は何も出ない
- [ ] 先行入力の感覚: 技の硬直の終わりの少し前（4 フレーム以内）に次の技のボタンを押すと、動けるようになった瞬間に次の技が出る。それより早く押したものは出ない。着地の直前に押しても同じ
- [ ] キャラなし（キャラ選択で「キャラなし」）では、棒人間は歩き・しゃがみ・ジャンプだけで、ボタンを押しても技は出ない。帯の場所に「キャラを選ぶと技のフレームが出ます」と出る
- [ ] キャラやゲームを変えて練習画面に入り直すと、棒人間は左寄り（真ん中より左）の立ちに戻り、帯と文は空（「技を出すと、フレームがここに出ます」）に戻る
- [ ] English で、見出しが「Move frame meter」、文が `Standing LP (5LP) — Startup 4F / Active 3F / Recovery 7F / Total 13F`（必殺技は `Spiral Arrow (236LK)`）、キャラなしの文が英語になる
- [ ] スマホ幅（ブラウザを狭くする）で、ステージが画面の幅いっぱいに収まり、棒人間がつぶれない。帯が折り返しても、ページ全体は横にはみ出さない。ブラウザの拡大・縮小やウィンドウの大きさの変更で、棒人間が消えない
- [ ] 処理が止まったとき（タブを切り替えて戻る）、棒人間が立ちに戻る。技の途中だったときは、帯が止まって残る
- [ ] 処理の重さ: 歩き続けても、技を連打しても、入力履歴・判定・計測（計測パネルの「描画の間隔」）が重くならない。何も動かしていないとき（立っているだけ）に、ステージが無駄に描き直されていない（開発者ツールの Performance で、立っている間の Canvas 描画が出ない）
- [ ] FAT の数字を実機と見比べる: 手元のゲームのトレーニングモードのフレームメーターと、キャミィの 5LP・5HK・2MP・236HK・623HK、ブリジットの 5S・2HS・632146S を見比べる。特に、括弧つきの硬直（5HK の `19(21)`、2MP の `14(17)`）、持続が途切れる 236HK、ブリジットのジャンプの空中 31F（推測）が合っているか
